* Abstract

This project implements a real-time computer vision system designed to assist visually impaired individuals in indoor navigation. The system leverages the YOLOv8x model trained on the Open Images v7 dataset to detect objects, DeepSORT for multi-object tracking, and Flask for web-based deployment. The application provides real-time audio feedback about detected objects, their locations, distances, movement patterns, and collision warnings.

Key features include:
- Real-time object detection using YOLOv8x-OIV7 (600+ object classes)
- Multi-object tracking with DeepSORT for temporal consistency
- Gyroscope-based rotation correction for mobile devices
- Spatial audio announcements with directional information
- Collision prediction and warning system
- A* pathfinding for safe navigation routes
- Web-based interface accessible from any device with a camera
- Dashboard monitoring system for admin/helper staff with live camera feeds
- Voice-controlled privacy mode for camera streaming

The system achieves near-real-time performance (800ms detection cycle) on CPU, making it practical for deployment on consumer hardware while maintaining safety-critical response times for blind navigation.

*** 2. Session-Based Tracker Management (app/services/object_tracker.py)

#+BEGIN_SRC python
class ObjectTrackingManager:
    def __init__(self):
        self.trackers = {}  # session_id -> DeepSort tracker
        self.track_histories = defaultdict(lambda: deque(maxlen=30))

    def get_tracker(self, session_id):
        """Get or create a tracker for a session with fallback options"""
        if session_id not in self.trackers:
            use_gpu = torch.cuda.is_available()
            tracker = None
            error_messages = []

            # Option 1: Try GPU with half precision (fastest)
            if use_gpu:
                try:
                    tracker = DeepSort(
                        max_age=10, n_init=2, nms_max_overlap=0.7,
                        max_cosine_distance=0.25, nn_budget=100,
                        embedder="mobilenet", half=True, embedder_gpu=True
                    )
                except Exception as e:
                    error_messages.append(f"GPU+half failed: {str(e)}")

            # Option 2: Try GPU without half precision (fast)
            if tracker is None and use_gpu:
                try:
                    tracker = DeepSort(
                        max_age=10, n_init=2, nms_max_overlap=0.7,
                        max_cosine_distance=0.25, nn_budget=100,
                        embedder="mobilenet", half=False, embedder_gpu=True
                    )
                except Exception as e:
                    error_messages.append(f"GPU failed: {str(e)}")

            # Option 3: Fallback to CPU mode (reliable)
            if tracker is None:
                tracker = DeepSort(
                    max_age=10, n_init=2, nms_max_overlap=0.7,
                    max_cosine_distance=0.25, nn_budget=100,
                    embedder="mobilenet", half=False, embedder_gpu=False
                )

            self.trackers[session_id] = tracker
#+END_SRC

*Purpose:* Manages separate DeepSORT trackers for each user session with robust error handling.

*Why Session-Based:*
- Allows multiple simultaneous users
- Each user has independent tracking state
- Prevents track ID conflicts between users

*Fallback Strategy (UPDATED 2025-10-19):*
Implements three-tier initialization to handle GPU/embedder failures:
1. *GPU + FP16:* Fastest option, tries first if GPU available
2. *GPU + FP32:* Falls back if FP16 fails (e.g., meta tensor error)
3. *CPU Mode:* Guaranteed fallback if all GPU attempts fail

This prevents "Cannot copy out of meta tensor; no data!" errors that occurred when PyTorch created the MobileNetV2 embedder model as a meta tensor (metadata without actual weights). The fallback ensures tracking always works, even with library version incompatibilities.

*DeepSORT Parameters Explained:*
- max_age=10: Track survives 10 frames without detection (UPDATED 2025-10-15: reduced from 30 to prevent false track associations during quick camera panning)
- n_init=2: Requires 2 consecutive detections before track is "confirmed" (UPDATED 2025-10-15: reduced from 3 for faster track initialization)
- nms_max_overlap=0.7: Non-maximum suppression threshold for overlapping detections
- max_cosine_distance=0.25: Maximum cosine distance between appearance features for matching (UPDATED 2025-10-15: reduced from 0.4 for stricter appearance matching and better discrimination between similar objects)
- nn_budget=100: Maximum number of appearance features stored per track
- embedder="mobilenet": Uses MobileNet for extracting appearance features
- half=True/False: Uses FP16 precision for 2x speed (when GPU+FP16 successful)

*** 4. IoU-Based Deduplication (app/utils/filtering.py & app/utils/geometry.py)

#+BEGIN_SRC python
# Geometry - app/utils/geometry.py
def calculate_iou(box1, box2):
    """Calculate Intersection over Union"""
    x1_min, y1_min, x1_max, y1_max = box1
    x2_min, y2_min, x2_max, y2_max = box2

    # Intersection area
    intersect_x_min = max(x1_min, x2_min)
    intersect_y_min = max(y1_min, y2_min)
    intersect_x_max = min(x1_max, x2_max)
    intersect_y_max = min(y1_max, y2_max)

    intersection = max(0, intersect_x_max - intersect_x_min) * \
                   max(0, intersect_y_max - intersect_y_min)

    # Union area
    box1_area = (x1_max - x1_min) * (y1_max - y1_min)
    box2_area = (x2_max - x2_min) * (y2_max - y2_min)
    union = box1_area + box2_area - intersection

    return intersection / union if union > 0 else 0.0

# Filtering - app/utils/filtering.py
def deduplicate_same_class_detections(detections, iou_threshold=0.5):
    """Remove overlapping detections of same class"""
    # Group by class
    class_groups = {}
    for det in detections:
        cls = det['class_name']
        if cls not in class_groups:
            class_groups[cls] = []
        class_groups[cls].append(det)

    # Deduplicate within each group
    deduplicated = []
    for cls, group in class_groups.items():
        group_sorted = sorted(group, key=lambda x: x['confidence'],
                            reverse=True)
        kept = []
        for det in group_sorted:
            should_keep = True
            for kept_det in kept:
                iou = calculate_iou(det['bbox_xyxy'],
                                   kept_det['bbox_xyxy'])
                if iou > iou_threshold:
                    should_keep = False
                    break
            if should_keep:
                kept.append(det)
        deduplicated.extend(kept)

    return deduplicated
#+END_SRC

*Purpose:* Eliminates duplicate detections of the same object class.

*Algorithm:*
1. Group detections by normalized class name
2. Sort each group by confidence (highest first)
3. For each detection, check IoU with already-kept detections
4. If IoU > 0.5 with any kept detection, discard (it's a duplicate)
5. Otherwise, keep the detection

*Why Needed:*
- YOLO may detect both "person" and "face" for same individual
- After class mapping, both become "person" -> duplicates
- Prevents double-counting and redundant announcements
- Keeps only the highest-confidence detection

#+BEGIN_SRC python
def calculate_movement(trajectory):
    """Calculate movement from trajectory points"""
    if len(trajectory) < 2:
        return {
            'direction': 'stationary',
            'speed': 0,
            'displacement': 0
        }

    # Get first and last points
    start = trajectory[0]
    end = trajectory[-1]

    # Calculate displacement vector
    dx = end[0] - start[0]
    dy = end[1] - start[1]
    displacement = np.sqrt(dx**2 + dy**2)

    # Calculate speed (pixels per frame)
    speed = displacement / len(trajectory)

    # Calculate velocity components
    velocity_x = dx / len(trajectory)
    velocity_y = dy / len(trajectory)

    # Calculate angle (0 deg = right, 90 deg = down,
    #                180 deg = left, 270 deg = up)
    angle = np.degrees(np.arctan2(dy, dx))

    # Determine cardinal direction
    if displacement < 5:
        direction = 'stationary'
    elif -45 <= angle < 45:
        direction = 'moving_right'
    elif 45 <= angle < 135:
        direction = 'moving_down'
    elif angle >= 135 or angle < -135:
        direction = 'moving_left'
    else:
        direction = 'moving_up'

    # Classify speed
    speed_class = 'slow' if speed < 2 else \
                  'medium' if speed < 10 else 'fast'

    return {
        'direction': direction,
        'speed': float(speed),
        'speed_class': speed_class,
        'displacement': float(displacement),
        'angle': float(angle),
        'trajectory_length': len(trajectory),
        'velocity_x': float(velocity_x),
        'velocity_y': float(velocity_y)
    }
#+END_SRC

*Purpose:* Analyzes object movement from trajectory history.

*Algorithm:*
1. Extract start and end points from trajectory
2. Calculate displacement vector (dx, dy)
3. Calculate total displacement magnitude
4. Compute average speed (displacement / frames)
5. Compute velocity components (vx, vy)
6. Calculate movement angle using arctan2
7. Map angle to cardinal direction
8. Classify speed into slow/medium/fast

*Output:*
- Direction: stationary, moving_left, moving_right, moving_up, moving_down
- Speed: pixels per frame (numeric)
- Speed class: slow (<2px/f), medium (2-10), fast (>10)
- Angle: -180 deg to 180 deg
- Velocity components: for prediction

*** 6. Collision Prediction (app/services/collision_detector.py)

#+BEGIN_SRC python
def predict_collision(track_center, track_movement,
                     image_width, image_height,
                     prediction_frames=10):
    """Predict collision with user (camera center)"""
    # User is at camera center
    camera_center_x = image_width / 2
    camera_center_y = image_height / 2
    user_zone_radius = min(image_width, image_height) * 0.15

    # Current distance to user
    current_distance = euclidean(track_center,
                                 (camera_center_x, camera_center_y))

    # If stationary, no collision
    if track_movement['direction'] == 'stationary':
        return {
            'collision_risk': False,
            'time_to_collision': None,
            'collision_severity': 'none'
        }

    # Predict future position
    velocity_x = track_movement.get('velocity_x', 0)
    velocity_y = track_movement.get('velocity_y', 0)

    predicted_x = track_center[0] + (velocity_x * prediction_frames)
    predicted_y = track_center[1] + (velocity_y * prediction_frames)
    predicted_position = (predicted_x, predicted_y)

    # Distance at predicted position
    predicted_distance = euclidean(predicted_position,
                                   (camera_center_x, camera_center_y))

    # Check if approaching
    is_approaching = predicted_distance < current_distance

    # Calculate time to collision
    time_to_collision = None
    if is_approaching:
        speed = track_movement['speed']
        if speed > 0:
            distance_to_close = current_distance - user_zone_radius
            time_to_collision = distance_to_close / speed

    # Determine severity
    collision_risk = False
    collision_severity = 'none'

    if is_approaching:
        if predicted_distance < user_zone_radius:
            collision_risk = True
            collision_severity = 'high'  # Will enter user zone
        elif predicted_distance < user_zone_radius * 2:
            collision_risk = True
            collision_severity = 'medium'  # Getting close
        elif current_distance < user_zone_radius * 3:
            collision_risk = True
            collision_severity = 'low'  # Approaching from distance

    return {
        'collision_risk': collision_risk,
        'is_approaching': is_approaching,
        'time_to_collision': float(time_to_collision)
                            if time_to_collision else None,
        'collision_severity': collision_severity,
        'predicted_position': [float(predicted_x),
                              float(predicted_y)],
        'current_distance': float(current_distance),
        'predicted_distance': float(predicted_distance),
        'user_zone_radius': float(user_zone_radius)
    }
#+END_SRC

*Purpose:* Predicts potential collisions based on trajectory extrapolation.

*Algorithm:*
1. Define user position as center of frame
2. Define "user zone" as 15% of frame size (safety radius)
3. Calculate current distance from object to user
4. If object is stationary -> no collision risk

async function initializeModernGyroscope() {
    const sensor = new Gyroscope({ frequency: 60 });

    sensor.addEventListener('reading', () => {
        const now = Date.now();
        const dt = (now - gyroscopeData.integration_time) / 1000;

        gyroscopeData.x = sensor.angularVelocityX || 0;
        gyroscopeData.y = sensor.angularVelocityY || 0;
        gyroscopeData.z = sensor.angularVelocityZ || 0;

            gyroscopeData.rotation_y += gyroscopeData.y * dt;
            gyroscopeData.rotation_z += gyroscopeData.z * dt;
        }
        gyroscopeData.integration_time = now;
    });

    sensor.start();
    return true;
}

* Detection and Tracking: Detailed Explanation

** Overview

The detection and tracking system combines multiple computer vision techniques:

1. *Object Detection:* YOLOv8x identifies objects in each frame
2. *Object Tracking:* DeepSORT maintains consistent IDs across frames
3. *Movement Analysis:* Trajectory analysis provides direction and speed
4. *Collision Prediction:* Linear extrapolation estimates future positions
5. *Pathfinding:* A* algorithm plans safe navigation routes

** Detection Pipeline (Detailed)

*** Step 1: Image Acquisition

*Frontend captures frame:*
- Video stream from getUserMedia API
- 640x480 resolution (typical)
- JPEG compression at 80% quality
- Base64 encoding for JSON transmission

*Gyroscope data collection:*
- Angular velocities (rad/s) from gyroscope sensor
- Integrated over time to get rotation angles
- Calibrated to baseline orientation

*** Step 2: Image Preprocessing

*Backend processing:*
1. Decode base64 image to NumPy array
2. Convert RGB -> BGR (OpenCV format)
3. Apply rotation correction (0 deg, 90 deg, 180 deg, 270 deg)
4. Resize to max 640px dimension (performance)

*** Step 3: YOLO Detection

*Model: YOLOv8x-OIV7*
- Architecture: CSPDarknet backbone + PAN neck
- Input: 640x640 (letterboxed)
- Output: Bounding boxes + class probabilities
- Confidence threshold: 0.30
- IoU threshold (NMS): 0.65

*Detection format:*
- Class ID (0-600+)
- Confidence score (0.30-1.00)
- Bounding box [x1, y1, x2, y2]

*** Step 4: Post-Processing

1. *Class filtering:* Remove blacklisted classes
2. *Class normalization:* Map similar classes (man/woman -> person)
3. *Format conversion:* XYXY -> LTWH for DeepSORT
4. *Deduplication:* IoU-based removal of overlapping same-class detections
5. *Defensive filtering:* Remove None/invalid objects before collision detection (ADDED 2025-10-30)
   - Double-checks tracked_objects list for None values
   - Prevents AttributeError crashes in collision warning system
   - Defense-in-depth approach with filtering at multiple stages

** Multi-Object Tracking (Detailed)

*** DeepSORT Architecture

DeepSORT combines three components:

1. *Motion Model (Kalman Filter):*
   - State vector: [x, y, w, h, vx, vy, vw, vh]
   - Predicts next position based on velocity
   - Updates predictions with measurements

2. *Appearance Model (MobileNet):*
   - Extracts 512-dim feature vectors
   - Enables re-identification after occlusion
   - Distinguishes similar objects

3. *Association (Hungarian Algorithm):*
   - Matches detections to existing tracks
   - Cost matrix: 50% IoU + 50% appearance similarity
   - Optimal assignment minimizes total cost

*** Tracking Life Cycle

*States:*
- *Tentative:* New track, not yet confirmed (<2 matches) (UPDATED 2025-10-15)
- *Confirmed:* Track has >=2 consecutive matches (UPDATED 2025-10-15)
- *Lost:* Track not matched for <10 frames (UPDATED 2025-10-15)
- *Deleted:* Track not matched for >=10 frames (UPDATED 2025-10-15)

** Movement Analysis (Detailed)

*Input:* Trajectory of last 30 positions (deque)

*Calculations:*
1. Displacement: sqrt(dx^2 + dy^2)
2. Speed: displacement / frames
3. Velocity: (dx/frames, dy/frames)
4. Angle: atan2(dy, dx) * 180/pi
5. Direction: Cardinal mapping based on angle
6. Speed class: slow (<2), medium (2-10), fast (>10)

*Output:*

  "velocity_y": 3.33

** Collision Prediction (Detailed)

*Model:* Linear extrapolation with constant velocity assumption

*Algorithm:*
1. Define user zone: 15% of frame radius around center
2. Calculate current distance to user
3. Predict position 10 frames ahead: pos + velocity * 10
4. Check if approaching: predicted_distance < current_distance
5. Estimate time to collision: (distance - radius) / speed
6. Classify severity:
   - High: predicted_distance < 15% frame
   - Medium: predicted_distance < 30% frame
   - Low: current_distance < 45% frame

*Assumptions:*
- Constant velocity (linear motion)
- User stationary at camera center
- 2D planar motion (no depth)

*Limitations:*
- Cannot predict non-linear trajectories
- Assumes no sudden stops/turns
- 10-frame horizon (~8 seconds at 800ms intervals)

*Vision-Based Position Tracking (Primary Method):*

The system uses visual odometry from tracked objects and depth estimation:

#+BEGIN_SRC python
def estimate_camera_movement(detections, previous_detections, previous_position):
    1. Match tracked objects between frames (by track_id)
    2. For each matched object with good depth data (confidence > 0.3):
       - Calculate distance_change = prev_distance - curr_distance
       - Negative change: camera moved toward object
       - Positive change: camera moved away from object
    3. Convert distance change to pixel movement (100 pixels per meter)
    4. Calculate movement vector: direction_to_object * pixel_movement
    5. Weighted average of all estimates (weight by distance_confidence)
    6. Return new_position and overall confidence score
#+END_SRC

*Requirements for Vision-Based Tracking:*
- Minimum 2 tracked objects with track_id
- Both frames must have distance confidence > 0.3
- Distance change > 0.1 meters (filters noise)
- Valid bounding boxes for object center calculation

*Time-Based Fallback:*
When vision confidence is low (<= 0.3):
- Calculate time elapsed since last update
- Assume movement toward goal direction
- Speed: 100 pixels/second (approx 1 meter/second)
- Update: new_pos = old_pos + goal_direction * speed * time

*Hybrid Approach Benefits:*
- Primary: Real visual odometry from scene
- No assumption user follows directions
- Works with any camera movement (forward, backward, sideways, turning)
- Fallback: Time-based when tracking insufficient
- Graceful degradation in challenging scenarios

*Session Management:*
- Position persists across navigation requests
- Previous detections stored for frame comparison
- Goal change resets position to starting point
- /reset_navigation clears all tracking data
- Session cleared when goal is reached

*** Reactive Navigation

*Real-time obstacle avoidance designed for dynamic environments:*

*Algorithm:*
1. Calculate direct vector to goal
2. Analyze obstacles in scene:
   - Distance (from depth estimation or bbox heuristic)
   - Direction relative to goal path
   - Movement state (static vs. moving)
   - Threat score = proximity + alignment + movement
3. Sample 16 candidate directions (-90 to +90 degrees)
4. Score each direction:
   - Bonus: Alignment with goal (+10 points)
   - Penalty: Obstacle proximity and alignment
   - Penalty: Moving obstacles (1.5x multiplier)
   - Penalty: Near screen edges
5. Select best direction (highest score)
6. Generate voice guidance based on deviation angle

*Voice Guidance Generation:*
- <10 degrees: "Walk straight ahead"
- 10-30 degrees: "Bear slightly left/right"
- >30 degrees: "Turn left/right"
- Distance: Real meters from depth estimation
- Warnings: Obstacles within 3 meters in path

*Side Detection (Fixed 2025-10-30):*
- Uses cross product of goal_direction and safe_direction vectors
- Positive cross product = object/direction is LEFT of reference
- Negative cross product = object/direction is RIGHT of reference
- Applied to both navigation directions and obstacle warnings
- Previous bug: left/right were inverted, now corrected

*** A* Pathfinding (Legacy Static Mode)

*Occupancy Grid Creation:*
1. Discretize image into 20x20 pixel grid cells
2. Mark cells occupied by bounding boxes as obstacles
3. Apply binary dilation (1 iteration) for safety margin

*Example:*

*** A* Search Algorithm

*Data structures:*
- open_set: Priority queue (min-heap by f_score)
- closed_set: Set of explored nodes
- came_from: Parent map for path reconstruction
- g_score: Actual cost from start
- f_score: Estimated total cost (g + h)

*Heuristic:* Manhattan distance
#+BEGIN_SRC python
h(a, b) = |ax - bx| + |ay - by|
#+END_SRC

*Main loop:*
#+BEGIN_SRC python
1. Initialize open_set with start node
2. While open_set not empty:
   a. Pop node with lowest f_score
   b. If node == goal: return reconstruct_path()
   c. For each neighbor:
      - Skip if obstacle or out of bounds
      - Calculate tentative g_score
      - If better than known g_score:
        * Update came_from, g_score, f_score
        * Add to open_set
3. Return None (no path found)
#+END_SRC

*Path reconstruction:*
#+BEGIN_SRC python
path = [goal]
while goal in came_from:
    goal = came_from[goal]
    path.append(goal)
path.reverse()
return path
#+END_SRC

*** Path Safety Scoring

*Algorithm:*
For each waypoint, find minimum distance to nearest obstacle (within 7x7 region):
#+BEGIN_SRC python
safety = min(min_distance / 3.0, 1.0)
overall_safety = mean(all_waypoint_safeties)
#+END_SRC

*Interpretation:*
- 1.0: Perfect (no obstacles within 3 cells)
- 0.7-1.0: Safe path
- 0.4-0.7: Caution advised
- 0.0-0.4: Risky path

** Object Tracking Lifecycle and Stale Track Management (UPDATED: 2025-10-16)

*** Overview

The original implementation had a critical timing issue:
1. Canvas cleanup happened in ui.js with a 3-second stale threshold
2. Announcement cleanup happened at the END of announceDetections() in detection.js
3. This created a race condition where objects could be announced BEFORE cleanup

* Depth Estimation System (MAJOR UPDATE: 2025-10-19)

** Overview

*PERFORMANCE REVOLUTION (2025-10-19 10:53):* The depth estimation system has been completely redesigned with Depth Anything V2 and async processing, achieving 10-20x performance improvement while maintaining accuracy. The system went from 200-350ms total latency down to 12-20ms, meeting the <15ms target for real-time blind navigation.

Previous iterations:
- *Original (pre-2025-10-18):* Bbox-based heuristics (~100 pixels = 1 meter) - highly inaccurate
- *First upgrade (2025-10-18):* MiDaS depth estimation - accurate but slow (200-350ms total)
- *Current (2025-10-19):* Depth Anything V2 + async processing - fast AND accurate (12-20ms total)

** Problem with Bbox-Based Distance

The original approach in [[file:app/services/pathfinder.py][pathfinder.py:435]] used:
#+BEGIN_SRC python

#+END_SRC

*Issues:*
- Same bbox size can mean different real distances
- Large person far away vs. small person close up look similar
- No accounting for camera FOV, focal length, or sensor properties
- Completely inaccurate for blind navigation safety

** New Async Depth Architecture (2025-10-19)

*** Key Performance Breakthrough

The system now runs depth estimation in a *background thread*, completely eliminating the performance penalty on the main detection pipeline:

- *Main Thread:* YOLO (7ms) + Tracking (10ms) = 17ms total (non-blocking!)
- *Background Thread:* Depth Anything V2 inference (14ms) runs continuously
- *Result:* Main pipeline never waits for depth - always uses cached result

*** Five-Tier Distance Estimation Hierarchy

*Priority 1: Motion-Based Calibration (NO HEIGHT ASSUMPTIONS!)*
   - Uses accelerometer step detection to track user movement
   - Learns depth scale from actual distance traveled vs. depth changes
   - Formula: scale = distance_traveled / depth_change
   - Works for ALL objects regardless of their height
   - Confidence threshold: >10% (accepts preliminary calibration)
   - Method: motion_calibrated (icon: person walking emoji)
   - See Motion-Based Calibration section for details

*Priority 2: Auto-Calibrated Depth (NEW: 2025-10-19!)*
   - Automatically learns depth scale from pinhole estimates
   - Uses rolling median of 20 calibration samples
   - Formula: real_distance = relative_depth * auto_learned_scale
   - Works for ALL objects once calibrated (even unknown classes!)
   - Requires 3+ samples to activate (50% confidence)
   - Method: auto_calibrated
   - Confidence increases with more samples (90% at 10+ samples)

*Priority 3: Pinhole Camera Model (Fallback):*
   - Uses known object heights (person ~1.7m, car ~1.5m, etc.)
   - Formula: distance = (known_height * focal_length) / bbox_pixel_height
   - Provides absolute metric scale for depth map
   - Fast mathematical calculation (no ML inference)
   - Now case-insensitive: "Computer monitor" = "computer monitor"
   - LIMITATION: Only works for 500+ known object classes

*Priority 4: Bbox Heuristic (NEW: 2025-10-19)*
   - Estimates distance from bbox size + vertical position
   - Formula: distance = 5.0 / sqrt(bbox_area_ratio) * position_factor
   - Objects lower in frame treated as closer (position_factor: 0.7-1.3)
   - Clamped to 0.5-20m range
   - Low confidence (0.3) but always available
   - Method: bbox_heuristic

*Priority 5: Failed (None)*
   - Distance marked as None with proper validation
   - Navigation uses pixel-based fallback
   - Collision detection uses pixel-based prediction

        """

        if class_name not in KNOWN_OBJECT_HEIGHTS:

        known_height = KNOWN_OBJECT_HEIGHTS[class_name]
        bbox_height = bbox[3] - bbox[1]

        return distance if 0.1 < distance < 100 else None

class DepthEstimator:
    def __init__(self, model_type='depth-anything-v2-small', force_cpu=False):
        """

        - Replaced MiDaS with Depth Anything V2 Small (10x faster)

        - Auto-calibration system learns depth scale
        - Thread-safe depth map caching
        """

        model_name = "depth-anything/Depth-Anything-V2-Small-hf"
        self.transform = AutoImageProcessor.from_pretrained(model_name)

        # Use device_map to prevent meta tensor errors
        if DEPTH_USE_FP16 and self.device == 'cuda':
            self.model = AutoModelForDepthEstimation.from_pretrained(
                model_name,
                device_map={"": self.device},
                torch_dtype=torch.float16
            )
        else:
            self.model = AutoModelForDepthEstimation.from_pretrained(

                device_map={"": self.device} if self.device == 'cuda' else None
            )
            if self.device == 'cpu':
                self.model.to(self.device)

        # Thread-safe caching
        self.depth_cache = DepthMapCache(maxlen=10)

        # Auto-calibration (learns scale from pinhole)
        self.auto_calibrator = AutoCalibrator(window_size=20)

        # Start async worker thread
        if DEPTH_ASYNC_ENABLED:
            self.async_worker = AsyncDepthWorker(
                self.model, self.transform, self.device,
                self.depth_cache, input_size=256  # Reduced from 384
            )
            self.async_worker.start()

    def estimate_distance_with_depth(self, image_bgr, bbox, class_name,
                                     motion_scale=None, motion_confidence=0.0):
        """
        Hybrid depth estimation with motion calibration priority.

        NEW (2025-10-18 14:45): Accepts motion calibration data (NO HEIGHT ASSUMPTIONS!)

        Args:
            motion_scale: Depth scale from user movement (meters per depth unit)
            motion_confidence: Confidence in motion calibration (0-1)

        Returns:
            {
                'distance': float (meters),
                'confidence': float (0-1),
                'method': 'motion_calibrated' | 'depth_calibrated' | 'pinhole' | 'failed'
            }
        """
        # Run depth every N frames (cached otherwise)
        if self.frame_counter % DEPTH_INFERENCE_INTERVAL == 0:
            self.last_depth_map = self.estimate_depth(image_bgr)

        # Get depth at bbox location
        if self.last_depth_map is not None:
            relative_depth = self.get_depth_at_bbox(self.last_depth_map, bbox)

            # Use pinhole for absolute scale
            pinhole_distance, confidence = self.pinhole_model.estimate_distance_with_confidence(bbox, class_name)

            if pinhole_distance is not None:
                return {
                    'distance': pinhole_distance,
                    'confidence': max(confidence, 0.7),
                    'method': 'depth_calibrated'

**** Graceful Shutdown and GPU Cleanup (ADDED 2025-10-19 15:49)

The async depth worker requires proper cleanup to avoid GPU context corruption. Without cleanup, stopping the server with Ctrl+C would leave CUDA resources locked, requiring manual process termination.

**Cleanup Mechanisms:**

#+BEGIN_SRC python
# 1. Signal Handlers (run.py)
def cleanup_and_exit(signum=None, frame=None):
    """Called on Ctrl+C or kill signal."""
    from app.services.depth_estimator import _depth_estimator
    if _depth_estimator is not None:
        _depth_estimator.cleanup()
    sys.exit(0)

signal.signal(signal.SIGINT, cleanup_and_exit)   # Ctrl+C
signal.signal(signal.SIGTERM, cleanup_and_exit)  # kill command

# 2. Explicit Cleanup Method (depth_estimator.py)
def cleanup(self):
    """Cleanup async worker and GPU resources."""
    # Stop worker thread gracefully
    if self.async_worker is not None:
        self.async_worker.stop(timeout=3.0)  # Wait up to 3s

    # Clear GPU memory
    if self.device == 'cuda':
        torch.cuda.empty_cache()

# 3. Thread Join with Timeout (AsyncDepthWorker.stop())
def stop(self, timeout=2.0):
    """Stop thread gracefully."""
    self.running = False
    if self.is_alive():
        self.join(timeout=timeout)  # Wait for thread to finish

# 4. Atexit Handler (backup cleanup)
def _cleanup_on_exit():
    """Backup cleanup if signal handler fails."""
    global _depth_estimator
    if _depth_estimator is not None:
        _depth_estimator.cleanup()

atexit.register(_cleanup_on_exit)
#+END_SRC

**Why Multiple Cleanup Layers?**

1. *Signal handlers:* Primary cleanup on Ctrl+C
2. *Explicit cleanup():* Guaranteed cleanup call
3. *Thread join:* Prevents forceful thread termination
4. *Atexit handler:* Backup if signals fail
5. *GPU cache clear:* Releases CUDA resources

**Shutdown Sequence:**
1. User presses Ctrl+C
2. SIGINT handler calls cleanup_and_exit()
3. DepthEstimator.cleanup() stops async worker
4. AsyncDepthWorker.stop() sets running=False and joins thread
5. Worker thread exits gracefully from run() loop
6. GPU memory cache cleared with torch.cuda.empty_cache()
7. Process exits cleanly without GPU errors

**Result:**
- Server can restart immediately without GPU errors
- No more "CUDA initialization failure" errors
- No need for manual taskkill /f /im python

# Caching decorator for metric methods (Added 2025-10-31)
def cache_metric(cache_duration: float = 3.0):
    """Cache metric results to reduce psutil overhead"""
    def decorator(func: Callable):
        cache = {'result': None, 'timestamp': 0}
        @wraps(func)
        def wrapper(*args, **kwargs):
            current_time = time.time()
            if current_time - cache['timestamp'] > cache_duration:
                cache['result'] = func(*args, **kwargs)
                cache['timestamp'] = current_time
            return cache['result']
        return wrapper
    return decorator

class ServerMonitor:
    def __init__(self):
        self.start_time = time.time()
        self.request_count = 0
        self.error_count = 0
        self.total_inference_time = 0.0
        self.inference_count = 0

    # Core monitoring methods (cached with @cache_metric decorator)

**** No Audio Playback on Client
- *Check:* Browser console for errors
- *Issue 1:* AudioContext requires user gesture (click page first)
- *Issue 2:* Device volume muted or very low

- *Detailed Fix:* See VOICE_CALL_TROUBLESHOOTING.md Issue 2

**** High Latency (>1 second)
- *Cause:* Network congestion or slow server
- *Check:* Ping server, check network speed
- *Mitigation:* Reduce chunk size (advanced setting)
- *Optimal Settings:*
  - Fast LAN: 100ms poll / 200ms chunks
  - WiFi: 150ms poll / 300ms chunks
  - Slow network: 200ms poll / 400ms chunks
- *Detailed Fix:* See VOICE_CALL_TROUBLESHOOTING.md Issue 3

**** Voice Indicator Doesn't Appear
- *Check:* Element exists: =document.getElementById('voiceIndicator')=
- *CSS Issue:* Check z-index and display properties
- *JS Error:* Check console for JavaScript errors
- *Detailed Fix:* See VOICE_CALL_TROUBLESHOOTING.md Issue 2
