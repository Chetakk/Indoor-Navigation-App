#+title: Backbone Architectures in Object Detection
#+filetags: :backbone:architecture:feature_extraction:cnn:

* Core Concept

Backbone is the feature extraction network that processes raw images into hierarchical feature representations.

Role: Transform pixels into semantic features usable for detection tasks.

* Purpose in Detection Pipeline

** Feature Extraction
- Input: RGB image (e.g., 640x640x3)
- Output: Multi-scale feature maps
  - High-resolution: Fine spatial details
  - Low-resolution: Semantic information

** Pre-training
Most backbones pre-trained on ImageNet:
- 1000 classes, 1.2M images
- Learns general visual features
- Transfer learning to detection

** Position in Architecture
```
Input Image
    |
    v
Backbone (Feature Extractor)
    |
    v
Neck (Feature Aggregation)
    |
    v
Head (Detection)
```

* Historical Evolution

** VGG (2014)
Architecture:
- 16-19 layers
- Small 3x3 convolutions throughout
- Max pooling for downsampling
- Simple, uniform structure

Characteristics:
- Very deep for its time
- 138M parameters (VGG-16)
- Computationally expensive
- Strong baseline

Usage in Detection:
- Faster R-CNN
- SSD
- Early YOLO variants

** ResNet (2015)
Revolutionary innovation: Skip connections

Architecture:
```
        x
        |
    +---+---+
    |       |
    |    Conv Block
    |       |
    +---+---+
        |
      ReLU
```

Key Features:
- Residual learning: F(x) + x
- Solves vanishing gradient problem
- Enables very deep networks (50-152 layers)
- Bottleneck design: 1x1 -> 3x3 -> 1x1

Variants:
- ResNet-50: 25M params, standard choice
- ResNet-101: More capacity, slower
- ResNet-152: Maximum capacity

Usage in Detection:
- Faster R-CNN
- Mask R-CNN
- RetinaNet
- Early YOLO versions

Benefits:
- Excellent feature quality
- Well-studied and reliable
- Good speed-accuracy trade-off

** DarkNet (2016-2018)
Custom backbone for YOLO

*** DarkNet-19 (YOLOv2)
- 19 convolutional layers
- Batch normalization throughout
- Mostly 3x3 convolutions
- Global average pooling

*** DarkNet-53 (YOLOv3)
- 53 convolutional layers
- ResNet-style skip connections
- No pooling (stride-2 convs)
- 41.6M parameters

Characteristics:
- Optimized for detection (not classification)
- Faster than ResNet-152
- Better accuracy than ResNet-101
- Efficient on GPUs

** CSPDarknet (2020)
Cross Stage Partial DarkNet (YOLOv4/v5)

Innovation: Split feature maps into two parts
```
Input
  |
  +---------+
  |         |
  v         v
Part1    Part2 (through dense block)
  |         |
  +---------+
      |
   Concat
```

Benefits:
- Reduces computation (fewer connections)
- Better gradient flow
- Lower memory usage
- Maintains accuracy

Usage:
- YOLOv4
- YOLOv5
- Scaled-YOLOv4

** EfficientNet (2019)
Compound scaling approach

Key Idea: Scale depth, width, and resolution together
```
depth = alpha^phi
width = beta^phi
resolution = gamma^phi
alpha * beta^2 * gamma^2 ≈ 2
```

Variants:
- B0: Baseline (5.3M params)
- B1-B7: Progressively larger
- Excellent efficiency

MBConv blocks:
- Inverted bottleneck
- Squeeze-and-excitation
- Depthwise separable convolutions

Usage in Detection:
- EfficientDet
- Modern YOLO variants

** MobileNet (2017-2019)
Designed for mobile and edge devices

*** MobileNetV1
- Depthwise separable convolutions
- Massive parameter reduction
- 4.2M parameters

*** MobileNetV2
- Inverted residual blocks
- Linear bottlenecks
- Even more efficient

*** MobileNetV3
- Neural architecture search
- Hard-swish activation
- Optimized for hardware

Usage in Detection:
- SSD-MobileNet (mobile deployment)
- YOLO-mobile variants
- Edge TPU applications

** Vision Transformers (ViT) (2020)
Attention-based architecture (no convolutions)

Architecture:
- Image divided into patches
- Patches embedded
- Transformer encoder
- Global attention

Variants for Detection:
- Swin Transformer: Hierarchical features
- PVT: Pyramid Vision Transformer
- Deformable DETR backbone

Trade-offs:
- Excellent performance with large data
- Higher computational cost
- Different inductive biases than CNNs

* Design Principles

** Hierarchical Features
Progressive downsampling creates pyramid:

*** Stage 1 (High Resolution)
- Output: H/4 x W/4
- Features: Edges, textures
- Receptive field: Small

*** Stage 2
- Output: H/8 x W/8
- Features: Patterns, parts

*** Stage 3
- Output: H/16 x W/16
- Features: Object components

*** Stage 4 (Low Resolution)
- Output: H/32 x W/32
- Features: Semantic concepts
- Receptive field: Large

*** Stage 5
- Output: H/64 x W/64
- Features: Global context

** Downsampling Strategies

*** Max Pooling
- Traditional approach (VGG, AlexNet)
- Non-learnable
- Information loss

*** Strided Convolutions
- Learnable downsampling
- Modern preference
- Better feature preservation

*** Both
- Convolution for features
- Pooling for downsampling
- Separate concerns

** Channel Progression
Typical pattern:
- Start: 64 channels
- After downsample: Double channels
- End: 512-2048 channels

Rationale:
- High-res: Spatial detail (many pixels, few features)
- Low-res: Semantic detail (few pixels, many features)
- Maintains computational balance

* Backbone Selection Criteria

** 1. Speed vs Accuracy
*** Fast Backbones
- MobileNet: Mobile/edge devices
- ShuffleNet: Efficient channel mixing
- GhostNet: Cheap operations
- Trade accuracy for speed

*** Balanced
- ResNet-50: Industry standard
- CSPDarknet-53: YOLO standard
- Good compromise

*** Accurate
- ResNet-101/152: High capacity
- EfficientNet-B7: Maximum quality
- Slow but best results

** 2. Model Size
*** Lightweight (<10M params)
- MobileNetV3
- EfficientNet-B0
- Edge deployment

*** Medium (10-50M params)
- ResNet-50 (25M)
- DarkNet-53 (41M)
- Standard choice

*** Large (>50M params)
- ResNet-152 (60M)
- EfficientNet-B7 (66M)
- When accuracy critical

** 3. Input Resolution
Different backbones optimized for different resolutions:
- MobileNet: 224x224
- ResNet: 224x224 (pre-training), flexible
- EfficientNet: Compound scaling includes resolution

Higher resolution:
- Better small object detection
- More computation
- More memory

** 4. Pre-training Dataset
*** ImageNet-1K
- Standard (1000 classes)
- Most common
- Good general features

*** ImageNet-21K
- More classes (21,000)
- Better features
- Requires more training

*** COCO Pre-training
- Detection pre-training
- Better for detection tasks
- Less common

** 5. Hardware Constraints
*** GPU
- Any backbone viable
- Batch size limited by memory

*** CPU
- Lightweight backbones (MobileNet)
- Optimize for inference

*** Mobile/Edge
- MobileNet, EfficientNet-B0
- Quantization-friendly
- TensorRT/CoreML optimization

* Backbone Modifications for Detection

** Multi-Scale Output
Expose intermediate layers:
```python
# ResNet example
c3 = layer3_output  # 1/16 resolution
c4 = layer4_output  # 1/32 resolution
c5 = layer5_output  # 1/64 resolution
```

Used in FPN, YOLO neck
See [[id:20251015130800-feature_pyramid_networks][Feature Pyramid Networks]]

** Remove Classification Head
- Detection doesn't need ImageNet classifier
- Remove final FC layer
- Keep feature extraction only

** Dilated Convolutions
Replace downsampling with dilation:
- Maintain resolution
- Expand receptive field
- Used in DeepLab, some detection methods

** Deformable Convolutions
Learnable spatial sampling:
- Adapt to object shape
- Better feature alignment
- Used in Deformable DETR

* Training Strategies

** Transfer Learning
Standard approach:
1. Load ImageNet pre-trained weights
2. Freeze backbone initially (optional)
3. Train detection head
4. Optionally fine-tune backbone

Benefits:
- Faster convergence
- Better performance with limited data
- Standard practice

** Backbone Fine-tuning
Strategies:
- Freeze completely: Fast, lower accuracy
- Freeze batch norm: Stable, good results
- Freeze early layers: Balance
- Fine-tune all: Best performance, slower

Learning rates:
- Backbone: Lower LR (1e-4)
- Head: Higher LR (1e-3)
- Prevents catastrophic forgetting

** Training from Scratch
Possible but requires:
- Large dataset
- More epochs
- Careful initialization
- Strong data augmentation

Usually worse than pre-training

* Modern Trends

** Neural Architecture Search (NAS)
Automated backbone design:
- EfficientNet: Compound scaling
- RegNet: Design space exploration
- Once-for-all: Dynamic networks

Benefits:
- Optimal architectures
- Better efficiency

Drawbacks:
- Expensive search
- May not generalize

** Hybrid Architectures
Combine CNNs and Transformers:
- Early layers: CNN (local features)
- Later layers: Transformer (global context)
- Examples: CoAtNet, CMT

** Efficient Architectures
Focus on deployment:
- Quantization-friendly
- Pruning-friendly
- Hardware-aware design
- TensorRT optimization

** Self-Supervised Pre-training
Alternative to ImageNet:
- MoCo, SimCLR, DINO
- Learn from unlabeled data
- Sometimes better than supervised

* YOLO-Specific Backbones

** YOLOv1-v2
- Custom CNN
- DarkNet-19

** YOLOv3
- DarkNet-53
- 53 convolutional layers
- ResNet-style connections

** YOLOv4
- CSPDarknet-53
- Cross Stage Partial connections
- More efficient

** YOLOv5/v6/v7
- CSPDarknet variants
- Scaled versions (n/s/m/l/x)
- Highly optimized

** YOLOv8/v11
Modern CSP-based backbone with significant architectural improvements

*** Architecture Overview
YOLOv8 uses a CSPDarknet-inspired backbone with C2f modules:
- Replaces C3 modules (YOLOv5) with C2f modules
- More gradient flow paths
- Better feature learning
- Improved speed-accuracy trade-off

*** C2f Module (CSP Bottleneck with 2 Convolutions)
Key innovation in YOLOv8 backbone:
```
Input
  |
  +------------------+
  |                  |
  v                  v
Conv 1x1          Conv 1x1
  |                  |
  |            +-----+-----+
  |            |           |
  |            v           v
  |      Bottleneck   Bottleneck (repeated n times)
  |            |           |
  |            +-----+-----+
  |                  |
  +------------------+
         |
      Concat
         |
      Conv 1x1
```

Benefits over C3:
- Lighter architecture (fewer parameters)
- More gradient paths (all bottlenecks concatenated)
- Better feature reuse
- Faster inference

*** Backbone Structure (YOLOv8n example)
Layer-by-layer breakdown:

**** Stem
- Conv 3x3, stride=2, channels: 3->16
- Conv 3x3, stride=2, channels: 16->32

**** Stage 1 (P2 features)
- C2f module, n=1, channels: 32->64
- Output: H/4 x W/4 x 64

**** Stage 2 (P3 features)
- Conv 3x3, stride=2, channels: 64->128
- C2f module, n=2, channels: 128->128
- Output: H/8 x W/8 x 128

**** Stage 3 (P4 features)
- Conv 3x3, stride=2, channels: 128->256
- C2f module, n=2, channels: 256->256
- Output: H/16 x W/16 x 256

**** Stage 4 (P5 features)
- Conv 3x3, stride=2, channels: 256->512
- C2f module, n=1, channels: 512->512
- Output: H/32 x W/32 x 512

Output: Three feature maps (P3, P4, P5) for neck processing

*** Scaled Variants
YOLOv8 offers 5 sizes with different depth and width multipliers:

**** YOLOv8n (nano)
- Depth multiple: 0.33
- Width multiple: 0.25
- Parameters: ~3.2M
- Use case: Mobile, edge devices

**** YOLOv8s (small)
- Depth multiple: 0.33
- Width multiple: 0.50
- Parameters: ~11M
- Use case: Embedded systems, fast inference

**** YOLOv8m (medium)
- Depth multiple: 0.67
- Width multiple: 0.75
- Parameters: ~25M
- Use case: General purpose, balanced

**** YOLOv8l (large)
- Depth multiple: 1.0
- Width multiple: 1.0
- Parameters: ~43M
- Use case: High accuracy requirements

**** YOLOv8x (extra-large)
- Depth multiple: 1.0
- Width multiple: 1.25
- Parameters: ~68M
- Use case: Maximum accuracy, server deployment

*** Key Improvements over YOLOv5
1. C2f replaces C3:
   - Split-concatenate design
   - More gradient pathways
   - Better information flow

2. Anchor-free detection:
   - Backbone outputs feed anchor-free head
   - Simpler pipeline

3. Optimized channel scaling:
   - Better width/depth balance
   - More efficient parameter use

4. SPPF (Spatial Pyramid Pooling - Fast):
   - Between backbone and neck
   - Efficiently increases receptive field
   - Three sequential 5x5 max pools (faster than parallel)

*** Activation Functions
- SiLU (Swish) throughout backbone
- Formula: x * sigmoid(x)
- Better gradient flow than ReLU
- Smooth, non-monotonic

*** Normalization
- Batch Normalization after every convolution
- Helps training stability
- Improves convergence speed

*** Design Principles
1. Gradient flow optimization:
   - Multiple paths through C2f
   - Skip connections
   - Prevents vanishing gradients

2. Feature reuse:
   - Concatenation in C2f
   - All intermediate features combined
   - Richer representations

3. Computational efficiency:
   - Fewer parameters than competitors
   - Optimized for modern GPUs
   - Fast inference speed

4. Multi-scale features:
   - Outputs at 1/8, 1/16, 1/32 resolutions
   - Enables detection at different scales
   - Fed to PAN-FPN neck

*** Training Characteristics
Pre-training options:
- COCO pre-trained weights available
- Can train from scratch with sufficient data
- Transfer learning recommended

Backbone fine-tuning:
- Usually fine-tuned end-to-end
- Lower learning rate than head
- Batch norm statistics updated

Data augmentation:
- Mosaic augmentation (default)
- MixUp, CopyPaste
- Strong augmentation helps backbone generalization

*** Performance Characteristics
YOLOv8n (nano) example:
- Speed: ~1.47ms @ batch=1 (TensorRT FP16)
- mAP50-95: ~37.3% (COCO)
- Parameters: 3.2M
- FLOPs: 8.7G

YOLOv8x example:
- Speed: ~3.53ms @ batch=1 (TensorRT FP16)
- mAP50-95: ~53.9% (COCO)
- Parameters: 68.2M
- FLOPs: 257.8G

*** Comparison with Other YOLO Backbones
vs YOLOv5:
- 10-20% faster inference
- Similar or better accuracy
- Fewer parameters (at same scale)

vs YOLOv7:
- Simpler architecture
- Easier to understand and modify
- Competitive performance

vs YOLOv4:
- More modern design
- Better gradient flow
- Easier training

*** Implementation Details
Written in PyTorch:
- Uses Conv + BN + SiLU as basic block
- C2f module is core building block
- Modular, easy to modify

Export capabilities:
- ONNX, TensorRT, CoreML
- Quantization support (INT8)
- Mobile deployment ready

Our CV-Project uses YOLOv8 for real-time object detection:
- Backbone extracts features from camera feed
- Outputs multi-scale features to neck
- Optimized for edge deployment
- Balance between speed and accuracy critical
