* Overview

This is an org-roam Zettelkasten knowledge base for the CV Project (Indoor Navigation System for the Visually Impaired). It contains atomic, interconnected notes covering both theoretical foundations and implementation details.

** What is Zettelkasten?

Zettelkasten (German for "slip box") is a knowledge management system based on:
- Atomic notes: One concept per note
- Linking: Notes connect via [[id:]] links, not hierarchy
- Emergence: Organization emerges from connections

** What is org-roam?

org-roam is an Emacs package that implements Zettelkasten principles using org-mode:
- Timestamp-based IDs (20251015HHMMSS format)
- Bidirectional linking via [[id:]] syntax
- Database for fast searching and backlinks
- Emacs integration for seamless navigation

* Folder Structure

We use a hybrid approach: domain-based folders with flat structure within each domain.

#+BEGIN_SRC
zettelkasten/
├── yolo/          # YOLO-specific concepts (8 notes)
├── cnn/           # CNN and deep learning fundamentals (4 notes)
├── detection/     # Object detection architectures (3 notes)
└── codebase/      # Project implementation notes (13+ notes)
#+END_SRC

** Why Folders?

While traditional Zettelkasten is flat, we use folders for:
1. Visual organization when browsing files
2. Conceptual clarity (theory vs implementation)
3. Scalability as the knowledge base grows
4. No impact on org-roam functionality (IDs work across folders)

* Using org-roam in Emacs

** Setup
1. Install org-roam: M-x package-install RET org-roam RET
2. Configure org-roam-directory: (setq org-roam-directory "path/to/zettelkasten")
3. Build database: M-x org-roam-db-sync

** Key Commands
- M-x org-roam-node-find :: Find or create notes
- M-x org-roam-node-insert :: Insert link to note
- M-x org-roam-buffer-toggle :: Show backlinks sidebar
- M-x org-roam-graph :: Visualize note connections
- C-c C-o :: Follow link under cursor

** Navigation
- TAB :: Fold/unfold sections
- C-c C-n :: Next heading
- C-c C-p :: Previous heading
- C-c C-u :: Up to parent heading

* Note Format

Every note follows this structure:

#+BEGIN_EXAMPLE
:PROPERTIES:
:ID:       20251015130000-note_name
:ROAM_ALIASES: "Alternative Name" "Alias"
:ROAM_REFS: [[file:../../app/services/detection.py::42]]
:END:
#+title: Note Title
#+filetags: :tag1:tag2:tag3:

* Core Concept
Main explanation...

* Section 1
Content...

* Related Concepts
- [[id:other-note-id][Other Note Title]]

* Footnotes
[fn:1] Additional information
#+END_EXAMPLE

** Key Elements
- :ID: - Unique timestamp-based identifier
- :ROAM_ALIASES: - Alternative names for searching
- :ROAM_REFS: - Links to source code (for codebase notes)
- #+filetags - Flexible categorization
- [[id:]] links - Connect to other notes

* Timestamp ID Format

Format: YYYYMMDDHHMMSS-descriptive_slug.org

Example: 20251015130000-yolo_architecture_fundamentals.org
- 2025 - Year
- 10 - Month (October)
- 15 - Day
- 13 - Hour (1 PM)
- 00 - Minute
- 00 - Second
- yolo_architecture_fundamentals - Human-readable slug

** Why Timestamps?
1. Guaranteed uniqueness (no ID collisions)
2. Chronological ordering
3. org-roam standard
4. Links use ID, so moving files doesn't break links

* Linking Strategy

** Within Same Domain
Notes in same folder heavily reference each other:
- YOLO notes link extensively within yolo/
- CNN notes form foundational network

** Cross-Domain
Theory notes link to implementation:
- yolo/architecture -> codebase/yolo_detector_class

** Emergent Organization
- Don't force hierarchies
- Let connections emerge naturally
- Use tags for multiple categorizations
- Folders are just visual aids

* Growth Strategy

** Adding New Notes
1. Create with timestamp: 20251015HHMMSS-new_concept.org
2. Add to appropriate domain folder
3. Include :ID: property matching filename (no .org)
4. Link from related existing notes
5. Add relevant tags
6. Run: M-x org-roam-db-sync

** When to Create New Domain Folder
Create new domain when:
- 5+ notes on distinct topic
- Clear conceptual separation
- Different from existing domains
- Examples: algorithms/, training/, deployment/

** Refactoring Notes
- Split large notes into atomic concepts
- Merge overly fragmented notes
- Update links (org-roam handles renames via IDs)
- Re-sync database after changes
