* Description

Samples multiple candidate directions around the goal direction and scores
each based on goal alignment and obstacle proximity. Returns the best scoring
(safest) direction for user to walk.

Core obstacle avoidance algorithm for reactive navigation.

* Parameters

- goal_direction :: np.ndarray - Normalized [x,y] vector toward goal
- obstacles :: list[dict] - Obstacle info from calculate_reactive_navigation
- start :: [x, y] - Current user position
- image_width :: int - Image width (for boundary checking)
- image_height :: int - Image height (for boundary checking)

* Returns

- np.ndarray :: Normalized [x,y] direction vector (safe walking direction)

** 2. Score Each Direction

For each angle offset:
#+begin_src python
test_angle = goal_angle + angle_offset
test_direction = [cos(test_angle), sin(test_angle)]

score = 0

# Goal alignment (want to move toward goal)
goal_alignment = dot(test_direction, goal_direction)
score += goal_alignment * 10  # High weight

# Obstacle penalties
for obs in obstacles:
    if obs['in_path']:
        obs_direction = obs['direction']
        alignment = dot(test_direction, obs_direction)

        if alignment > 0.3:  # Obstacle in this direction
            penalty = alignment * (50 / max(obs['distance'], 10))
            if obs['is_moving']:
                penalty *= 1.5  # Extra penalty for moving
            score -= penalty

# Boundary penalties (don't guide into edges)
test_pos = start + test_direction * 100  # Project ahead
if test_pos[0] < 50 or test_pos[0] > width - 50:
    score -= 20
if test_pos[1] < 50 or test_pos[1] > height - 50:
    score -= 20

if score > best_score:
    best_score = score
    best_direction = test_direction
#+end_src

Example penalties:

- Obstacle 50px away, alignment 1.0, moving: -1.5
- Obstacle 100px away, alignment 0.5, stationary: -0.25

* Sampling Resolution

16 samples = 180deg / 16 = 11.25deg resolution

Trade-offs:
- Fewer samples (8): Faster, less precise
- More samples (32): Slower, more precise

16 is good balance for real-time performance.

* Edge Cases

** All Directions Blocked
Always returns SOME direction (best available)
Never fails - degradation is graceful

** No Obstacles
Returns goal_direction (score = 10)

** Goal Behind User
Goal alignment becomes negative
May still find best direction if obstacles present

** Multiple Moving Obstacles
Each contributes penalty
Cumulative effect finds safest gap

* Performance

- Time complexity: O(samples * obstacles) = O(16 * n)
- Typical: 16 * 5 = 80 iterations
- Each iteration: ~10 operations
- Total: < 1ms typically
- Negligible compared to API latency

* Comparison to Other Algorithms

** vs Potential Fields
- Potential: Smooth gradients
- Sampling: Discrete directions
- Potential: Can get stuck in local minima
- Sampling: Less prone to local minima

** vs Dynamic Window Approach
- DWA: Considers robot dynamics (velocity, acceleration)
- This: Assumes immediate direction change (human walking)
- DWA: More complex
- This: Simpler, sufficient for walking navigation

** vs Vector Field Histogram
- VFH: Builds polar histogram of obstacles
- This: Direct scoring of sampled directions
- VFH: Better for cluttered environments
- This: Simpler, faster
