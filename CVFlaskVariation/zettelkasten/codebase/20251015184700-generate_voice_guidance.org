* Description

Converts reactive navigation output (safe direction vector, obstacles, distance)
into natural language voice guidance for blind users.

Generates context-aware messages with:
- Direction instructions (walk straight, turn left, etc.)
- Distance to goal
- Obstacle warnings

* Parameters

- safe_direction :: np.ndarray - Safe walking direction from find_safe_direction()
- goal_direction :: np.ndarray - Direct direction to goal
- distance_to_goal :: float - Distance to goal in pixels
- obstacles :: list[dict] - Obstacle list sorted by threat

* Returns

dict with:
- primary :: str - Main navigation message
- warnings :: list[str] - Obstacle warnings
- full_message :: str - Complete message (primary + warnings)

* Natural Language Design

** Principles

1. Concise - Short messages for quick comprehension
2. Actionable - Clear what user should do
3. Spatial - Use relative directions (left/right)
4. Contextual - Include relevant obstacles only
5. Natural - Human-like phrasing

** Vocabulary

Direction words:
- Walk straight ahead
- Bear slightly left/right
- Turn left/right

Distance words:
- almost there
- X meters
- X meters ahead

Obstacle descriptors:
- person on right
- moving car on left
- obstacle ahead

** Alternatives Considered

More detailed:
- "Turn 30 degrees to the right" - Too technical
- "Walk forward for 4.5 meters" - False precision

Less detailed:
- "Go right" - Not clear if turn or bear
- "Keep walking" - No distance info

Current design balances detail and naturalness.

* Accessibility Considerations

** For Blind Users

- Spatial awareness - "on right/left" relative to walking direction
- Movement awareness - "moving" prefix for dynamic obstacles
- Distance awareness - "almost there" vs "5 meters ahead"
- Urgency implicit - Warnings indicate close obstacles

** Audio Priority

Frontend assigns priority based on warnings:

priority = 'medium'  // For navigation guidance

* Limitations

** Distance Accuracy

Pixel-to-meter conversion is rough approximation:
- No depth information
- Assumes typical distances
- Varies with camera angle
- Different for different object types

Better with depth sensors or monocular depth estimation.

** Obstacle Position

"on right/left" is 2D projection:
- Doesn't indicate if obstacle is high/low
- Doesn't indicate if obstacle is far/close in depth
- 2D camera limitation

** Language

Currently English-only:
- Could be internationalized
- Different cultures may prefer different phrasing
