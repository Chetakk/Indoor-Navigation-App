#+title: Auto-Calibration System
#+filetags: :calibration:depth_estimation:optimization:

* Concept

Auto-calibration automatically learns the *scale factor* to convert relative depth values from Depth Anything V2 into metric distances (meters) by comparing with pinhole camera estimates.

This solves the scale ambiguity problem: we get relative depth (0-1000 arbitrary units) but need real distances (0-10 meters).

* The Scale Ambiguity Problem

Monocular depth models output *relative depth* - they know what's closer/farther but not actual distances:

#+BEGIN_EXAMPLE
Relative depth: [100, 200, 500, 800]
Could mean: [1m, 2m, 5m, 8m]
Or: [2m, 4m, 10m, 16m]
Or: [0.5m, 1m, 2.5m, 4m]
#+END_EXAMPLE

We need to find the *scale*: =real_distance = relative_depth * scale=

* How Auto-Calibration Works

** 1. Collect Calibration Samples

For each detected object:
1. Get relative depth from Depth Anything V2
2. Get metric distance from pinhole camera model [fn:1]
3. Calculate scale: =scale = metric_distance / relative_depth=

Example:
#+BEGIN_SRC python
# Person at relative depth 378.66
relative_depth = 378.66

# Pinhole estimates 3.14 meters (from bbox height + focal length)
pinhole_distance = 3.14

# Calculate scale
scale = 3.14 / 378.66 = 0.00829  # meters per depth unit
#+END_SRC

** 2. Filter and Store

- Only accept reasonable scales (0.001 to 0.1)
- Store in rolling window (last 20 samples)
- Use collections.deque for efficient FIFO queue

** 3. Compute Robust Estimate

- Use *median* instead of mean (robust to outliers)
- Require minimum 3 samples before activating
- Confidence increases with more samples (50% at 3, 90% at 10+)

** 4. Apply to All Objects

Once calibrated, apply scale to ALL objects (even unknown classes!):
#+BEGIN_SRC python
if auto_scale is not None:
    metric_distance = relative_depth * auto_scale
    # Now we have real meters for ANY object!
#+END_SRC

* Why Median Filter?

Pinhole estimates can be noisy (wrong class, partial occlusion, etc.).

Median is robust to outliers:
- [0.008, 0.009, 0.008, *0.100*, 0.009] -> median = 0.009 (good!)
- Mean would be 0.027 (corrupted by outlier)

* Implementation Details

#+BEGIN_SRC python
class AutoCalibrator:
    def __init__(self, window_size=20):
        self.scales = deque(maxlen=20)  # Rolling window
        self.lock = threading.Lock()    # Thread-safe

    def add_sample(self, pinhole_dist, relative_depth):
        if pinhole_dist and relative_depth > 0:
            scale = pinhole_dist / relative_depth
            if 0.001 <= scale <= 0.1:  # Sanity check
                with self.lock:
                    self.scales.append(scale)

    def get_scale(self):
        with self.lock:
            if len(self.scales) < 3:
                return None  # Need minimum samples
            return float(np.median(list(self.scales)))

    def get_confidence(self):
        n = len(self.scales)
        if n < 3: return 0.0
        if n < 10: return 0.5 + (n / 20.0)  # 0.5-1.0
        return 0.9  # High confidence
#+END_SRC

* Advantages

1. *Fully Automatic*: No manual calibration needed
2. *Works for All Objects*: Not limited to known classes
3. *Robust*: Median filter handles noisy estimates
4. *Adaptive*: Continuously updates with new data
5. *Fast*: <1ms computation overhead

* Limitations

1. *Requires Known Objects*: Needs some objects in pinhole database to bootstrap
2. *Initial Delay*: Needs 3+ samples before activating
3. *Scene Dependent*: Scale may vary if camera zoom changes
4. *Assumes Fixed Scale*: Real world has varying scales

* When It Activates

Priority in distance estimation hierarchy [[file:050-distance-fallback-hierarchy.org][(see note 050)]]:

1. Motion calibration (if user has walked)
2. *Auto-calibration* (if 3+ samples collected) <- THIS
3. Pinhole only (for known objects)
4. Bbox heuristic (fallback)

* Performance

- Computation: <0.1ms per frame
- Memory: ~80 bytes (20 floats)
- Thread-safe: Works with async processing
